# 砚 · INKBOARD

单文件前端 + 零依赖服务端的**实时协作白板**。5 个人打开同一个链接，就在同一块画布上：看得见彼此的光标、谁在编辑哪张便签，改动实时同步。

- 前端：`inkboard.html` 一个文件，Canvas + DOM 混合渲染，**无框架、无构建**；云端备份按云服务技能走 CDN 形式的 `@tencent-ai/workbuddy-cloud-sdk`，加载失败会降级并明说
- 后端：`server.js` 一个文件，**零 npm 依赖**——WebSocket 握手与帧编解码全部手写（RFC 6455），只用 Node 内置的 `http` / `crypto` / `fs` / `path`

## 在线协作地址

**https://inkboard.app.workbuddy.host/?room=team-a**

换掉 `room=` 后面的名字就是另一块独立画布。直接把这个链接发给 4 个队友，5 人实时同屏。

> 纯静态预览（GitHub Pages，无服务端，只能单机）：https://ujunn.github.io/inkboard/

## 跑起来

```bash
node server.js                 # 默认 8080
PORT=3000 node server.js       # 换端口
```

然后 5 个人都打开 **同一个房间链接**：

```
http://<你的地址>/?room=team-a
```

房间号就是 `?room=` 后面的字符串，换一个就是另一块独立画布。页面顶栏右侧有个**邀请按钮**，点一下把带房间的链接复制走，发给队友即可。

> 局域网：队友用你的内网 IP 访问，例如 `http://192.168.1.20:8080/?room=team-a`

## 协作能力

| 能力 | 实现 |
| --- | --- |
| 画布同步 | 新增/移动/缩放/改色/改文字/删除便签，笔迹，连线，全部实时广播 |
| 实时光标 | 各端光标带名字与身份色，随缩放平移正确定位 |
| 编辑占用提示 | 某人双击编辑某张便签时，其他人看到该便签被对方颜色描边 + "XX 正在编辑"名牌 |
| 在线成员 | 顶栏头像栈 + 实时人数，最多 20 人/房间 |
| 后进者补齐 | 新人进来先拉全量快照，立刻看到已有内容 |
| 断线重连 | 指数退避自动重连，断线期间的操作会缓存并在重连后补发 |
| 刷新不丢 | 服务端持有画布状态，并防抖落盘到 `data/<room>.json`，重启也不丢 |
| 跨重启不丢 | 画布同时防抖备份到云数据库 `boards` 表，服务端连数据一起丢了也能从云端恢复 |
| 单机兜底 | 完全连不上服务端时自动降级为本地可用模式，不会白屏 |

## 同步协议

JSON over WebSocket，全部文本帧。操作是**细粒度 op** 而不是整盘快照，这样两个人同时改不同便签不会互相覆盖：

```
n+ 新增便签      {k:'n+', note}
n~ 修改便签      {k:'n~', id, patch:{x,y,w,h,color,text}}
n- 删除便签      {k:'n-', ids:[]}        服务端级联删相关连线
s+ 新增笔迹      {k:'s+', stroke}
s. 笔迹补点      {k:'s.', id, pts:[]}     绘制中增量追加，避免 O(n²) 流量
s- 删除笔迹      {k:'s-', ids:[]}
c+ / c- 连线     {k:'c+', conn}
```

控制消息：`hello` / `init` / `ops` / `cursor` / `edit` / `peer` / `leave` / `name`。

## 两个值得说的设计决定

**撤销不用整盘快照。** 多人场景下快照里混着别人的改动，一撤销就会把别人刚加的便签一起删掉。所以每次本地改动都同时算出**正向 op 和逆向 op**，撤销只回滚自己那一份，并通过广播让所有人看到。

**笔迹用增量补点而不是整条重传。** 一条 300 点的笔迹如果每帧重传整条数组，流量是 O(n²)。改成 `s.` 只追加新增的点。

## 前端渲染分三层

- **`#scene` canvas** — 网格与笔迹在世界坐标下绘制（笔迹随缩放变粗）；连线、框选、远端光标在**屏幕坐标**下绘制，保证线宽与箭头尺寸恒定
- **`#world` div** — 整体 `transform: translate(x,y) scale(k)`，承载便签 DOM，`contenteditable` 承担双击编辑；选中环用 `calc(1.8px / var(--z))` 反向补偿缩放
- **`#overlay` div** — 屏幕坐标层，放选中框、四角 resize 手柄、浮动操作条，尺寸不随缩放变化

## 两层存储：实时靠 WebSocket，长期靠云数据库

接入 WorkBuddy 云服务后，画布有两条互补的链路：

| | 管什么 | 载体 |
| --- | --- | --- |
| WebSocket 服务端 | **实时**——广播、光标、编辑占用、在线成员 | `server.js` |
| 云数据库 `boards` 表 | **长期**——整块画布的防抖快照，跨重启/重新部署仍在 | `public.boards(room PK, board JSONB, updated_at)` |

改动停下来约 2 秒后，前端把当前画布 upsert 一份到云端；切到后台会立刻刷一次。反过来，**第一个进空房间的人会先从云端找历史画布**，找到就恢复并广播给全房间，找不到才放示例内容。这样服务端内存或 `data/` 目录丢了（重启、重新部署）也不会回到空白。

RLS 是房间级公开读写（`USING (true)` / `WITH CHECK (true)`）——协作本身免登录，安全边界就是「谁知道房间名」。因为行是公开可写的，**从云端读回的画布会按服务端同款白名单重新校验一遍**（`sanitizeBoard`）才进 DOM，不信外来数据。

顶栏的**云端胶囊**显示当前状态：读取中 / 已存云端 / 保存中 / 备份失败，失败时悬停能看到具体原因，点一下可立即手动备份。

> 云端只认应用域名：从 `inkboard.app.workbuddy.host` 打开才启用，从 GitHub Pages 或本地打开会明确提示「云端备份只在应用域名下可用」，实时协作不受影响。

## 已知边界

- **不是 CRDT**，冲突是「后写覆盖」：两人同时拖同一张便签，以最后到达的为准；同时编辑同一张便签的文字同理。5 人轻量协作够用，要做严肃的并发编辑建议接 Yjs / Automerge。
- 笔迹不能单独选中或擦除，只能整条撤销。
- 无鉴权，知道房间号就能进。原型场景可接受；要上生产得加房间密码或登录。
- 服务端有容量护栏：单房间 800 便签 / 4000 笔迹 / 1500 连线，超出会丢弃最旧的笔迹。

## 验证过的场景

服务端 16 项协议测试、5 客户端并发、浏览器 ↔ Node 双向同步（含光标与编辑标记）全部通过。云服务接入后：本地无头 Chrome 冒烟（0 报错）+ 7 项交互断言（示例便签 / 双击新建 / 撤销 / 重做 / 迷你地图 / 云端状态条 / 无异常）全过。

## 设计定调

石墨黑顶栏 `#14161B`（叠 4% SVG 噪点避开塑料感）+ 暖白画布 `#FAFAF9`，强调色取**朱砂 `#E04A1F`**——刻意避开白底蓝紫渐变那套默认配色。便签用纸感六色，阴影带环境色而非纯黑。
